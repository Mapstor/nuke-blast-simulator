## 2. Real content dates

- **`data/content-dates.json`** — committed manifest, one entry per URL: `{ hash, datePublished, dateModified }`. `hash` is a SHA-256 of the page's main content with chrome, `<script>`, `<style>` and `<time>` elements stripped, so the hash is **date-independent** (writing a date never changes it).
- **`scripts/update-content-dates.mjs`** (+ shared `scripts/content-hash.mjs`) reads the prerendered `.next` HTML and moves `dateModified` to the commit date **only** for URLs whose hash changed; `datePublished` is seeded from the first git commit that introduced the route (blog from each article's own `datePublished`), never "today". Run this wave with `NBS_SEED=2026-10-15`.
- **Readers:** `src/lib/seo/contentDates.ts` → `getContentDates(path)`. The sitemap `lastmod`, `articleSchema` `datePublished`/`dateModified`, the blog visible "Updated" label, and `article:modified_time` all read the manifest. Nothing reads `new Date()` anymore.
- **Drift guard:** `tests/content-dates.test.ts` fails if any built page's hash differs from the manifest, if a built page is missing from the manifest, or if a manifest entry is stale — so a Vercel build can't silently refresh a date.
